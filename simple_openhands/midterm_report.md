# 中期检查报告

## 一、课题进展情况

本课题围绕“基于执行反馈的强化学习代码生成研究”展开，整体研究思路是将代码生成任务形式化为基于执行反馈的强化学习问题，在已有代码大模型基础上，通过监督微调与强化学习相结合的方法，提升模型在标准代码生成基准任务上的正确率与稳定性。课题前期主要聚焦于研究问题的拆解、实验环境的搭建、训练数据的整理以及初始模型的准备，中期阶段的核心工作则转向围绕 PPO 的强化学习闭环进行工程实现、联调验证和初步实验。

截至目前，课题的总体进展可以概括为“前期基础部分已经基本完成，中期重点工作已经从准备阶段进入实验阶段”。首先，在数据层面，已经完成 MBPP 和 HumanEval 两个代码生成数据集的收集、清洗、标准化、切分以及可执行性验证。原始数据在导入后并不能直接用于训练，需要统一字段结构、清除不规范文本、提取标准答案和测试代码，并保证每条样本都能够在本地环境中执行通过。经过整理后，当前项目已经形成了一套稳定的主数据集和训练数据集，能够同时服务于 SFT 阶段和 PPO 阶段。

其次，在运行环境层面，项目已经具备了支撑代码生成实验的基础条件。通过现有的 Simple OpenHands 运行时能力，已经完成代码执行接口、命令执行、文件读写、IPython 运行以及运行时验证等关键环节的联通。虽然目前正式的 Docker/FastAPI 强化学习环境类仍未完全封装为论文计划中理想化的 SandboxEnv 形式，但现有运行链路已经能够承担“生成代码—执行测试—返回反馈”的核心职责，为后续 PPO 环节提供了工程基础。

再次，在模型层面，已经完成基座模型选择、SFT 训练配置设计和第一轮监督微调实验。当前选定 Qwen2.5-Coder-1.5B 作为现阶段的主要实验基座，并采用 LoRA 的方式进行监督微调。一方面，这样的模型规模更适合当前可用算力和数据规模，另一方面也更便于在后续 PPO 阶段进行迭代调试。第一轮 SFT 已经训练完成，并产出一版可用的 adapter，用于后续强化学习的热启动。

最后，在强化学习部分，目前已经完成 PPO 训练前关键闭环的搭建，并完成了最小 PPO 更新版本的实现。具体来说，当前系统已经能够完成：读取 RL 样本、将 prompt 输入模型、生成代码、对生成代码执行测试、计算 reward、记录 old logprob、计算 advantage 和 return，并进一步用 PPO 的 clipped loss 对策略进行一次更新。后续又在此基础上补入了单步 value head、单步 GAE/return 以及相对 base policy 的 KL penalty，使实验框架从最初的 smoke test 版本逐步过渡到更接近正式研究所需的实验框架。

从计划完成度来看，课题原计划中的第一阶段工作，即“环境搭建与基座模型微调”，已经基本完成；第二阶段“强化学习算法实现与初步实验”也已经实质性启动，并且完成了最小闭环的跑通。目前真正的主要任务已经不再是“能否把代码写出来”或者“能否把链路打通”，而是围绕 PPO 的实验稳定性、奖励设计和超参数配置，继续迭代，使强化学习更新真正带来可观、可复现的性能提升。

## 二、课题研究已取得的阶段性成果

本阶段已经取得的成果主要体现在数据整理、监督微调、评测体系构建、强化学习桥接链路搭建以及 PPO 更新实现等五个方面。

第一，数据整理与验证工作已经形成完整闭环。课题首先完成了 MBPP 和 HumanEval 两个数据集的收集与标准化处理，统一为适用于代码生成训练和强化学习实验的 schema。每条样本都包含 prompt、entry_point、canonical_solution、test_code 等关键信息，并进一步派生出 SFT 与 RL 两套视图数据。当前得到的最终数据集中，sft_train.jsonl 共 385 条，sft_valid.jsonl 共 42 条，rl_valid.jsonl 共 42 条，rl_test_humaneval.jsonl 共 164 条。更重要的是，这些数据并非停留在“格式统一”的层面，而是完成了本地 Python 直跑验证和运行时环境验证：本地标准答案与测试代码可执行性验证达到 591/591 通过，MBPP train、MBPP valid 与 HumanEval test 的 runtime 复核也全部通过。这说明当前数据不仅在结构上可用，而且在执行层面是稳定可靠的，已经满足后续训练与实验的基本要求。

第二，监督微调（SFT）阶段已取得初步成果。基于 Qwen2.5-Coder-1.5B 和 LoRA 配置，课题已完成第一轮 SFT 热启动训练。为了适应当前数据规模和算力条件，实验中采用了相对保守但稳妥的训练配置，包括 max_length=1024、num_train_epochs=5、learning_rate=1e-4、gradient_accumulation_steps=8 等设置。实验结果表明，SFT 训练能够正常收敛，最终验证集损失约为 0.7472。从单题推理测试来看，模型已经能够按题目格式生成结构规范的 Python 函数代码，说明 SFT 阶段已经帮助模型建立起了对当前任务格式的初步适应能力。尽管此时模型逻辑正确性仍然不稳定，但它已经可以作为后续 PPO 的可用起点。

第三，已经建立起 Base 模型与 SFT 模型的基线对比体系。为了验证监督微调是否真正起效，课题完成了 Base 与 SFT 的初步 A/B 对比评测。早期在较小评测规模上，SFT 模型已表现出相对于 base 的正向提升；在后续统一 entry_point 对齐逻辑并稳定评测口径后，当前 SFT 模型在 rl_valid 全量 42 条样本上的表现为：full_pass_records = 24，Pass@1 = 0.5714，average_reward = 0.619。这一结果具有两个重要意义：一方面，它说明小样本 SFT 确实能够提高模型在代码生成任务上的完成质量；另一方面，它为后续 PPO 阶段提供了明确的比较基线，也就是后续任何 PPO 更新都应当至少不低于这组结果。

第四，已经完成 PPO 前“生成—执行—打分”桥接链路的实现。为了使后续强化学习不再停留在概念设计层面，本阶段重点完成了从模型输出到执行反馈的工程联通。当前系统已经能够读取 RL 样本，以 prompt 为输入让策略模型生成代码，再将生成结果与测试代码结合，在本地执行环境中运行，并返回 reward、通过样例数、总测试数、错误类型等信息。此外，系统还支持记录旧策略下的 logprob、样本级 reward 和 advantage，为 PPO update 提供输入。这条链的打通非常关键，因为它标志着强化学习部分已经不再依赖静态假设，而是具备了真实的可执行反馈来源。特别是在处理中发现，entry_point 对齐对于 reward 的准确性影响非常大。通过自动函数别名逻辑修正后，早期 rollout 的 average_reward 从 0.1 提升到 0.5，说明当前执行反馈链条已经能够产生更干净、更有效的学习信号。

第五，已经实现并验证了最小 PPO 更新版本。课题并未止步于 rollout 数据收集，而是进一步完成了单步 PPO 更新脚本的编写与联调。最初版本实现了 clipped policy loss 和单次 optimizer step；在此基础上又继续加入了 scalar value head、单步 GAE/return 计算以及相对于 base policy 的 KL penalty，使当前脚本不再只是演示性质的 smoke test，而具备了更完整的 PPO 结构。实际运行结果表明，当前 PPO update 能够正常输出 policy_loss、value_loss、kl_loss 和 avg_ratio 等指标，并能够成功更新参数、保存更新后的 adapter 和 value head。这说明从工程实现角度看，课题已经完成了从“数据—SFT—rollout—PPO update”的第一条完整实验链路搭建。

第六，已经完成 PPO 更新前后的首次全量效果对比。为了判断 PPO 更新是否真正带来收益，课题使用统一评测口径对更新前后的模型进行了 rl_valid 全量 42 条样本上的对比。结果显示，更新前 SFT 模型的指标为 Pass@1 = 0.5714、average_reward = 0.619；更新后模型的指标为 Pass@1 = 0.5476、average_reward = 0.5714。该结果表明，当前这组 PPO 更新设置尚未带来正向提升，并出现了轻微退化。但从另一个角度看，这也说明当前研究已经进入了真正意义上的实验调优阶段：问题不再是系统能否工作，而是当前参数选择、KL 约束强度和 rollout 规模是否合理。就中期阶段而言，这样的结果本身也具有研究价值，因为它直接暴露了当前 PPO 设计中最需要继续攻克的问题。

## 三、存在的问题及解决思路

虽然当前课题已经取得了较为完整的阶段性成果，但仍然存在若干关键问题，需要在下一阶段重点解决。

首先，当前 PPO 虽然已经能够运行，但尚未在验证集上带来优于 SFT baseline 的性能。全量对比结果显示，PPO 更新后模型在 Pass@1 和 average_reward 上都略低于更新前的 SFT 模型。这个现象说明，当前强化学习部分已经实现了“可训练”，但尚未达到“训练有效”。这并不意味着 PPO 思路错误，而更可能说明当前实验所用的超参数组合、reward 信号分布以及策略更新强度还不够合理。因此，后续工作的重点应转向系统调参，而不是重新推倒重来。

其次，KL 惩罚项的数值偏大，疑似成为抑制 PPO 性能增益的重要原因。在当前单步 PPO 实验中，mean_kl_loss 达到了较高水平，这说明策略更新过程中相对于 base/reference policy 的偏移被较强地惩罚。过大的 KL 惩罚会使策略难以朝更高 reward 的方向充分移动，表现为训练“形式上发生了更新”，但最终性能未见提升甚至轻微下降。对应的解决思路是优先围绕 kl_coef 展开调参，降低 KL 惩罚强度，并观察更新后 Pass@1 与 average_reward 的变化情况。

第三，当前 rollout 样本规模仍然偏小，导致 reward 信号和梯度估计稳定性不足。当前 smoke test 版本大量使用 10 条样本进行实验，这在工程联调阶段是必要的，但对于评估 PPO 的实际收益而言显然不够。样本规模过小意味着单批样本内的题目分布、错误类型和 reward 波动都会对更新结果产生过强影响，从而使实验结果缺乏稳定性和代表性。为此，下一阶段应逐步将 rollout 样本规模扩大到 rl_valid 全量 42 条，甚至进一步扩展到从 rl_train 中抽样 50 至 100 条，以提高策略更新与验证结果的可信度。

第四，当前 PPO 仍然是“单步 episode”的简化版本，尚未实现更完整的时序结构。当前代码生成任务中，每个 prompt 基本被视为一个单步 episode，因此价值函数、回报估计和优势计算都做了单步近似，这在当前阶段有助于快速打通闭环，但距离更完整、更加严格的 PPO 训练框架仍有差距。未来如果需要进一步提高实验说服力，可以逐步引入更完善的 critic 训练、更系统的 GAE 实现以及更细粒度的轨迹建模方式。不过，考虑到当前主要问题还在于“单步 PPO 未显现正向收益”，因此短期内并不建议立即大幅扩展算法复杂度，而应先在当前简化框架上完成调参与验证。

第五，当前 reward shaping 仍然较为粗粒度。虽然目前已经采用“按测试通过比例计分”的方式来为 PPO 提供比纯 0/1 更细的奖励信号，但这一设计仍然不足以充分反映生成代码的质量差异。例如，当前 reward 无法显式区分“函数名对齐错误”“语法错误”“逻辑部分正确但样例未全过”“运行正确但效率较低”等不同情况。后续如果在现有参数调优后仍难以获得稳定提升，则需要进一步细化 reward 设计，使模型获得更丰富、更有区分度的学习信号。

总体来看，当前存在的问题已经从“实现层面问题”转变为“实验设计和参数配置问题”。这意味着课题已经进入中期阶段应有的状态：基础工程已具备，当前需要依靠实验设计、调参与分析来推动性能提升。

## 四、下一阶段的工作计划和研究内容

下一阶段的工作将围绕“在现有可运行 PPO 框架基础上，通过系统调参与算法细化，争取实现相对于 SFT baseline 的稳定性能提升”这一目标展开。

首先，下一阶段将优先开展系统调参实验。当前最优先需要调节的参数包括 kl_coef、learning_rate 和 rollout 样本规模。实验上将采用控制变量的方法：首先保持其他条件不变，仅调整 kl_coef，比较不同 KL 惩罚强度下更新后模型在 rl_valid 全量样本上的 Pass@1 和 average_reward；若依然未获得提升，再进一步结合 learning_rate 的微调来寻找更合适的更新强度；之后再扩大 rollout 规模，观察样本规模扩大后 PPO 更新稳定性是否改善。通过这种由浅入深的实验策略，可以避免一次性改动过多因素而导致结论不清。

其次，下一阶段将扩大 PPO 的实验规模和评测覆盖面。当前已有的 smoke test 和全量验证主要证明了系统可以跑通，但尚不足以形成更有说服力的实验结果。下一步将进一步在 rl_valid 全量样本上持续开展 PPO 更新前后对比，并适当从 rl_train 中抽样更多样本构建 rollout batch，以提高 reward 分布和策略梯度估计的代表性。同时，还将继续记录并分析常见错误类型，如函数名不匹配、部分测试通过、逻辑性错误等，为后续 reward 设计和案例分析提供依据。

第三，下一阶段将继续完善 PPO 训练框架，使其逐步从当前的“单步可运行版”过渡到“更正式的实验版”。具体来说，一方面将继续强化 value 分支和 GAE 部分的稳定性；另一方面将进一步评估 KL 约束的合理性，并根据实验结果决定是否引入更稳健的 KL 估计方式。此外，还将考虑逐步完善 reward shaping，使模型在执行反馈中不仅接收到“通过了多少测试”的信息，也能更细粒度地感知代码质量差异。

第四，下一阶段将同步推进中期检查与后续论文材料的积累与整理。当前已经拥有较为完整的数据整理结果、SFT 训练结果、Base vs SFT 基线结果、PPO 闭环实现以及 PPO 更新前后对比结果。接下来需要将这些结果进一步系统化整理，包括实验配置、日志、关键曲线、错误样例与分析结论等，使之能够直接用于后续中期报告扩写、消融实验设计和最终论文撰写。

第五，若后续调参结果显示当前单步 PPO 已能带来稳定正收益，则下一阶段还将进一步探索更大 rollout 规模、更丰富 reward 设计和更规范的 PPO 训练流程；若调参后仍无明显改善，则会结合当前已有实验结果，对“执行反馈在小模型小样本条件下的收益边界”这一问题进行更深入分析，并适时调整强化学习部分的实验重心。

总体而言，下一阶段的核心任务不是继续证明系统“可以运行”，而是要让现有系统“运行得更有效”。通过围绕 kl_coef、learning_rate 和 rollout 规模的系统调参，并继续完善价值估计与奖励设计，预期能够逐步提升 PPO 在代码生成任务中的实际收益，为后续中期检查和最终论文研究奠定更加扎实的实验基础。
